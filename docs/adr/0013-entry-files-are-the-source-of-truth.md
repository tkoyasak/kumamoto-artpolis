# Entry files are the source of truth

Decided 2026-07-13.

## Context

`projects/` entries were generated by an importer driven by
`scripts/data/projects-registry.json` (ADR 0012): the registry held the
number → id assignment, split definitions, exclusions, and per-entry
overrides, and the importer wrote entry files it never touched again. Truth
about one entry was spread over two places — hand corrections (pinned
coordinates, fixed fields) lived in the md, while the registry still claimed
the override values — and the importer could neither verify an existing entry
against the prefecture pages nor tell which values were deliberate.

## Decision

The entry Markdown files are the single source of truth; the registry is
deleted. Everything the registry knew moves into the entries themselves:

- Each entry's frontmatter carries its source (`url`, the prefecture detail
  page; `pdfs`) alongside the catalog fields. Splits are simply several files
  sharing a `number`; overrides are simply the stored values.
- Excluded official-list rows (plans and programmes that are not buildings)
  become md files in the same collection, flagged `excluded: true` with
  `number`/`name`/`reason` only. The site never renders them — every consumer
  narrows through `isActive` (`src/lib/catalog.ts`) — they exist so the sync
  tool knows the number is accounted for.
- The importer becomes a sync tool (`scripts/sync-projects.ts`, ADR 0012's
  parsing/geocoding kept). It fills absent frontmatter fields (including
  number-only stubs a human creates for reported new rows), reports drift
  between stored values and the pages, and reports numbers no file accounts
  for. It never overwrites a stored value and never touches the body:
  frontmatter is data the tool may fill, the body is human-owned prose
  (official links moved out of bodies into `url`/`pdfs`). A reported diff is
  applied by editing the entry.
- `lat`/`lng`/`municipality` are fill-only, never diffed: geocoding is
  大字-centroid precision and outliers get hand-pinned, so a re-geocode always
  disagrees and the diff would be permanent noise.

## Consequences

- One place to read and correct an entry; hand corrections are first-class
  stored values, not shadow overrides, and drift against the prefecture pages
  is now detectable for every entry, not just new ones.
- New official numbers need a human step by design: the tool reports them,
  a human creates the `NNNN-<slug>.md` stub (id assignment stays a reviewed
  decision), the next run fills it. A freshly created stub fails
  `astro check` until that run completes — a transient local state.
- The excluded union makes the collection schema wider: every consumer must
  narrow via `isActive`, enforced by types.
- Numbers 64, 87, 121, 122 remain uncatalogued, now visibly so in every sync
  report: 64's 建築データ names both housing complexes in one record (the
  split names don't containment-match, and GSI cannot geocode 中杉田/矢津田),
  87/121/122 have proposal-stage pages with no building data. Completing them
  is deliberate manual work: create the stub, research the values, fill by
  hand.
